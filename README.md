# Chainfolio · ETH / BSC 本地钱包工作台

本机单用户网页，Node.js ≥ 22.13，使用 ethers 与 Node 内置 SQLite。

## 启动

```sh
npm install
npm start
```

打开 http://127.0.0.1:3088 。没有真实钱包时显示标注清楚的演示数据，点击“进入真实钱包”切换。演示数据不写入数据库。

点击右上角“网络设置”，填写 Ethereum / BSC 的 **主网 RPC**，点击“测试连接”验证，再保存。配置即时生效，不用重启。也可使用 `.env.example` 创建 `.env` 提供初始配置；网页保存的配置优先于环境变量。

## 钱包与资产

- 生成 1–100 个钱包，本地加密保存完成后自动查询本批钱包的双链余额及已配置代币。
- 导入 1–5000 个公开地址，或从 TXT / CSV 提取地址。重复地址不会重复创建，导入后自动查询。
- 备注、分组、地址/批次/备注搜索、批次与分组筛选、金额区间、ETH/BNB 余额排序。
- SQLite 服务端分页，8 / 20 / 50 行可选。勾选支持跨页；查询和导出优先作用于所选钱包，否则作用于当前筛选的全部结果。
- 支持单链、双链、单钱包、批次/分组查询；原生 ETH/BNB 与最多 20 个 ERC-20 / BEP-20 代币。
- 添加代币需填写对应网络的合约地址，验证并读取 `symbol` 与 `decimals` 后保存。支持标准字符串符号、0–36 位精度。移除配置不删除历史余额。
- 余额保留完整整数精度。失败不覆盖上次成功值，页面区分最后成功时间、最近尝试时间和错误；超过 5 分钟或本次失败标记过期。
- 原生币汇总包含最近一次成功值，显示有记录数量及过期数量。由于不同批次查询时间可能不同，汇总不是统一时间点的全账户快照。
- CSV 包括备注、分组、代币、原始整数余额、精度、每项成功/尝试时间、区块和错误。原始余额除以 10 的 decimals 次方得到显示金额；文本列处理了电子表格公式前缀。

## 持续自动运行与高余额 Tab

点击“自动运行”，输入加密密码即可持续执行 **生成 → 加密保存 → 查询 → 下一批**。没有总数量上限，也无需填写总批次数。默认每批 10 个、批次间隔 5 秒，可以调整每批 1–100 个和间隔 1–3600 秒；这些是速率控制，不是总量限制。

- 至少配置一条可用主网 RPC 才能启动。每批查询启动时已配置的网络，并包含代币配置。
- 点击“暂停自动运行”后等待当前写入或请求完成，不再创建新批次。已生成的钱包保留。
- 关闭网页不停止本地服务中的自动任务。停止或重启本地服务后，自动任务保持暂停；继续时必须输入原加密密码。密码仅保存在进程内存，不写入任务配置。
- 连续 3 批原生币余额全部查询失败，或可用磁盘不足 64MB，会自动暂停。运行持续消耗磁盘和 RPC 请求额度。
- “高余额钱包”Tab 使用 **ETH > 0.1 或 BNB > 0.1** 的条件，任意一条链满足即可；等于 0.1 不算，不叠加两条链的余额，也不使用代币余额。双链同时满足只显示一行。
- 高余额按最近一次成功的原生币余额筛选。后续查询失败时保留该行并标记过期；成功查询后余额下降到阈值以下，则自动移出高余额 Tab。钱包仍在“全部钱包”。
- 新生成且未收到转账的地址通常余额为零。此模式查询新生成的批次，不会周期性复查所有历史钱包；历史地址可使用批次/分组查询功能刷新。

## 任务与恢复

- “任务”展示最近 30 个任务；完整记录保存在数据库中。
- 持久化任务项与查询区块。服务意外中断后自动恢复未完成的查询；手动暂停的任务不会自动启动。
- 生成任务中断后需在任务页重新输入原密码。若已有钱包，会先验证原密码；已保存的钱包不重新生成。密码不写入任务数据。
- 暂停等待当前一组请求或密钥写入结束，不强行打断写盘。
- “仅重试失败项”创建新的查询任务，使用新的查询区块，不重复查询成功项。
- 每批最多 5 个请求，批次间隔 1 秒；单次请求 12 秒超时，最多尝试 3 次。429/暂时错误退避，遵守有上限的 Retry-After；凭据错误不重复请求。
- 暂时仅允许一个生成/查询任务运行。运行期间暂停配置和备份写操作，避免在任务中途切换网络。
- 同一生成请求 ID 重复提交返回原任务，防止网络重试时重复生成。

## 查看私钥

每个钱包行增加“私钥”列：本地有 keystore 的钱包可点击“查看私钥”，输入原加密密码后显示完整私钥，支持复制和手动隐藏。错误密码不会返回私钥，连续 5 次错误后等待一分钟再试。演示数据、只有公开地址的导入记录不包含私钥。解密只在本机执行，不调用 RPC；解密响应禁止缓存。

## 加密备份与恢复

“备份”支持下载加密 JSON 文件。整个备份使用 scrypt 派生密钥及 AES-256-GCM 加密，包含：钱包公开资料、备注与分组、最近余额、代币配置、原有加密 keystore。

**不包含 RPC URL / API Key 和任务记录。** 备份密码与每批钱包的原加密密码不同：恢复备份不会改变 keystore 原密码。

恢复前验证密码、认证标签及结构，再合并钱包；已有资料和余额不覆盖，缺失的加密密钥文件可补回。恢复中断后可以再次导入同一备份。备份明文最大 40MB、恢复请求最大 60MB、单个备份最多 10000 个钱包。规模更大时，在服务停止后备份完整 `data/` 目录。

## 文件与迁移

- `data/wallets.sqlite`：钱包资料、最新成功余额、最近查询状态、任务及任务项。
- `data/keystores/<钱包ID>.json`：标准加密 JSON keystore，文件权限 0600。
- `data/settings.json`：本机 RPC 凭据与代币配置，权限 0600；浏览器只显示 RPC 主机和配置状态，不回显完整凭据。
- `data/service.lock`：防止两个服务进程同时使用同一数据目录。

首次启动将旧 `data/wallets.json` 迁移到 SQLite，保留原清单不改写。加密文件通过临时文件写入、同步和原子重命名保存；启动时检查密钥目录，将写盘成功但尚未登记的密钥恢复到列表，提示缺失或异常文件。

目录权限 0700。运行中备份应使用网页功能；直接复制数据库时需先停止服务，避免漏掉 WAL 中的数据。不要删除原始加密文件。密码丢失无法恢复。

## 运行边界

服务只监听 `127.0.0.1`，包含 Host / Origin 校验、随机会话请求令牌以及内容安全策略。这仍是本机单用户工具，没有多用户权限和远程登录，不应直接开放公网。

私钥不随钱包列表接口返回、不导出到 CSV、不发送到 RPC。用户在“私钥”列点击查看并输入原加密密码后，才通过本机接口返回该钱包私钥并在页面显示；30 秒后或切换到后台时自动隐藏，不写入浏览器持久化存储。复制到剪贴板的内容不会自动清除。只读导入地址没有私钥，无法通过地址推导私钥。RPC 凭据保存于受文件权限保护的本机配置，未接入系统钥匙串。钱包密码在生成期间短暂存在服务端内存，任务结束后解除引用；JavaScript 不保证可靠擦除内存。

不包含交易、转账、行情估值、交易历史、资产变更通知或持续自动扫描。网络测试只验证当前节点连通性和主网 Chain ID，真实地址余额需要有效节点额度。新地址未收款时余额通常为零。
